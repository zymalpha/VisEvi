> 工作目录：`/ssd/visual_reasoning/zym/MedVisEvi/tool_verification/`。创建于 2026-10-30。
> 目标：确认 A1–A26 的 27 个接口**实现正确**，也就是代码按定义计算，模型类工具忠实复现作者的推理流程，坐标、侧别、单位和拒答语义都正确。
> **不在本方案范围内**：医学准确性的独立评估（结论“该模型在独立数据上表现如何”），以及功能层设计（`doc/未来计划.md` 第 8 节，已按用户决定暂缓）。

## 1. 什么叫“实现正确”：五级验证

| 级别 | 回答的问题 | 判定依据 | 适用 |
|---|---|---|---|
| V1 接口契约 | 输入校验、拒答、溯源、缓存绑定、schema 是否按约定工作 | 正例/反例全覆盖；每种拒答原因至少触发一次 | 全部 27 个接口 |
| V2 计算正确 | 确定性算法的数值是否正确 | ①手算幻影（phantom）；②**独立重写**的参照实现（暴力法或第三方库）在随机输入上逐例比对；③不变量/性质测试 | A9–A23、A12 两个接口的算术部分、A25 规则、A20–A23 |
| V3 流程对齐 | 模型类工具是否与**作者官方推理流程**给出相同结果（预处理、归一化、通道顺序、阈值、坐标回映） | 差分测试：同一批图分别经“官方流程脚本”和“我们的接口”，比较输出 | A1–A8、A12 自动、A18、A24–A26 |
| V4 变换一致性 | 坐标回映、侧别、尺寸处理有没有系统性错误 | 蜕变测试（metamorphic）：对输入做已知变换（补边、平移、缩放、整图左右翻转），检查输出是否按预期变化 | 全部输出坐标或 mask 的接口 |
| V5 预期表现核对 | 有没有“能跑但算错”的隐蔽错误（错归一化、错通道、轴转置） | 在**作者报告过的数据**或**模型训练集内的数据**上，表现应落在事先写定的宽松区间；明显塌陷即判实现有误。这一步**不作为准确性结论** | 有本地参照数据的模型工具 |

另外设一项**验证套件自检（变异测试）**：故意向被验证代码注入典型错误（交换 x/y、归一化写错、mask 偏移一像素、左右通道互换、阈值改成 0.4、坐标网格从 0–100 改成 0–1000 等），所有对应用例必须变红。若注入错误后套件仍全绿，说明这部分验证无效，需要补用例。

## 2. 逐工具验证设计

“容差”在执行前冻结。模型类比较基于同一设备、同一精度；跨设备的差异单独记录。

### 2.1 A1–A4 PSPNet（`segment_lungs/heart/mediastinum/shoulder_bones`）

- **V3 官方流程**：独立脚本只用 TorchXRayVision 官方示例流程，即 `xrv.datasets.normalize` → `XRayCenterCrop` → `XRayResizer(512)` → `model(img)` → `sigmoid > 0.5`。
  - 已知差异：我们的适配器用 torch bilinear antialias 缩放，官方用 skimage `resize`。
  - 先**量化差异**：逐通道 IoU、面积差。
  - 判定：IoU ≥ 0.98 视为等价；否则改为官方预处理并重新生成缓存。这一决定在执行前确认。
- **V4**：
  - 方图四周补零边后，mask 应整体平移，裁剪尺寸与补边一致；
  - 竖图、横图的中心裁剪偏移应等于 (W−s)/2、(H−s)/2；
  - 整图左右翻转后，`Right_*` 与 `Left_*` 的 mask 应近似互为镜像（IoU ≥ 0.9）。这一条若不成立，说明侧别来自位置而非解剖，需要记录。
- **V5**（宽松区间，执行前冻结）：
  - Montgomery 肺野：按 `leftMask↔Right_Lung` 映射，只在视野内计分，每侧 Dice 中位数 ≥ 0.85；
  - JSRT SCR 镜像的肺、心、锁骨：先确认 1024→2048 的坐标映射，肺 Dice 中位数 ≥ 0.85，心 ≥ 0.75，锁骨仅作记录。
- **V1**：缓存绑定的各类拒答、视野截断、EXIF 与高位深拒答（已有单测，纳入清单复核）。

### 2.2 A5 CheXmask-U HybridGNet（`locate_lung_landmarks`）

- **V3**：独立脚本按作者 `DataPreparation`（居中补零、1024、/255）与 `inferenceWithHybridGNet.py` 的解码方式推理，但取隐变量均值，与我们 `eval_sampling=False` 的设置一致，比较 120 个节点。判定：最大偏差 ≤ 0.5 px（1024 帧）。
  - 另跑一次作者原始的随机采样配置，记录它与均值输出的差异，作为“为何改用均值”的证据。
- **V4**：补边、缩放后节点坐标应按变换移动（容差 ≤ 2 px 原图）。
- **V5**：Montgomery 在其训练集中，把左右肺节点围成的多边形与人工肺 mask 比较，每侧 Dice 中位数 ≥ 0.90，失败即怀疑回映错误。语义节点表（0/21/29/44/65/71）在 Montgomery 全部 138 例上复核，应各自为几何极值；不一致的比例要报告。

### 2.3 A6/A7/A18/A24 CheXOne（`detect_abnormalities`、`ground_phrase`、`classify_roi_attributes`、`classify_view`）

- **V3**：独立脚本完全按模型卡示例写：`Qwen2_5_VLForConditionalGeneration` + `AutoProcessor`、`max_pixels=512*512`、贪心解码，输入同一提示词。判定：输出 token 序列**逐字相同**；选项字母首 token 概率差 ≤ 1e-3（bf16）。
- **框坐标**：用 ChestX-Det 参照框再做一次网格尺度检验（已做 6 例，扩到 ≥ 50 例），确认 0–100 网格与边坐标映射。A18 裁剪框偏移要用合成图核对：在已知位置画一个高亮方块，询问方块所在区域。
- **V4**：整图补边后，框应按变换平移（容差按网格分辨率，1 格 = 图宽的 1%）。
- **V5**（CheXOne 训练集内的数据，仅作实现核对）：
  - A24：NIH 300 张的 ViewPosition，准确率应 ≥ 0.85；JSRT、Montgomery 全为 PA，误判率记录；
  - A6：ChestX-Det 中 cardiomegaly、effusion 等类别的框命中率记录，仅作塌陷检查。
- **解析器**：从 V5 运行中收集全部原始回答，统计 `unparsed` 率，并人工抽查 ≥ 50 条解析结果。

### 2.4 A8 气胸（`segment_pneumothorax`）

- **V3**：独立脚本按作者仓库 `modeling.py` 的 `preprocess`（`albumentations.Resize`）走 `AutoModel(trust_remote_code)` 流程，与我们的 `cv2.resize` 实现比较。判定：概率图最大绝对差 ≤ 1e-4，mask 完全相同。
- **V4**：补边、缩放后 mask 应按变换移动。
- **V5**：ChestX-Det 气胸多边形仅作塌陷检查（模型训练来源不明，不设门槛，只记录分布）。

### 2.5 A12 心胸比（`measure_ctr` 自动、`compute_ctr_from_borders`）

- **V2**：
  - 胸廓内缘规则已有手算单测；补充随机合成肋骨 mask，与**独立暴力实现**逐行比对；
  - 比值部分用随机边界与手算比对。
- **V3（交叉实现）**：CXAS 作者自带的 CTR 提取器（`cxas/extraction/cardiothoracic_ratio.py`，按右膈顶行定中线、以肺最宽行作分母）在同一批图上运行。
  - 定义不同，**不要求相等**；
  - 要求两者高度相关（Spearman ≥ 0.8），并逐例解释大偏差。
- **V4**：左右翻转后 CTR 应基本不变（差 ≤ 0.02）；补边后不变。
- **人工复核**：在 ≥ 20 张多来源图上画出肋骨内缘线、心界线，人工判断内缘线是否落在肋骨内侧缘。这里只看“规则执行是否符合定义”，不判断 CTR 的医学正确性。

### 2.6 A25 图像质量（`assess_image_quality`）

- **V2**：旋转指数、膈顶上方肋骨计数、心后对比度、视野接触四条规则已有手算单测；补充独立重写与随机合成输入的比对。
- **V3（交叉实现）**：CXAS 作者的 `spinecenter_distance` 等特征提取可作旋转相关量的对照，同样只要求相关。
- **V4**：
  - 左右翻转后，旋转指数应变号；
  - 整图亮度线性变换后，肋骨计数不变，心后对比度按比例变化。
- **人工复核**：≥ 20 张图上画出锁骨内端、脊柱中线、膈顶、计入的肋骨编号，人工核对规则是否按定义执行。

### 2.7 A26 管线（`localize_devices`）

- **V3**：独立脚本直接调用作者运行时的 `LocalLinesTubesRuntime.predict(..., force_full_pipeline=True)`，按 `max` 档和作者原始的 `weights_only=False` 加载方式（只读本地已校验文件），与我们的 worker 比较。判定：存在分数差 ≤ 1e-4；ETT 尖端、隆突坐标完全相同；4 类线 mask 的 IoU ≥ 0.999。
  - 我们改用 `weights_only=True` 加载，这一步同时证明改动不影响结果。
- **V4**：补边、缩放后尖端与隆突坐标按变换移动（容差 ≤ 1% 图宽）。
- **V5**：本地没有设备标注，不做门槛；CheXlocalize 的 1 例 Support Devices 只作展示。

### 2.8 A9–A23 确定性工具

每个工具都要有三类证据：

1. **手算幻影**：已有，汇总成清单复核。
2. **独立参照实现**，在 ≥ 1000 个随机 mask 上逐例比对，覆盖空洞、多连通域、贴边、单像素、细线、各向异性 spacing：

   | 工具 | 参照实现 |
   |---|---|
   | A9 外接框/Feret | 暴力两两角点距离 |
   | A10 面积 | 计数 |
   | A11 间隙距离 | 暴力像素单元间距 |
   | A13 左右比较 | 逐行扫描 |
   | A14 形状 | 暴力边计数周长；凸包用 scipy 实现 |
   | A15 灰度 | numpy 直接计算 |
   | A16 纹理 | skimage `graycomatrix`/`graycoprops`，同量化 |
   | A17 清晰度 | scipy 卷积 |
   | A19 对称性 | 显式反射 |
   | A20 分区 | 逐像素中心判定 |
   | A21/A22 关系 | 像素级邻接判定，与 shapely 结果比对 |
   | A23 分布 | 逐连通域手工统计 |

   判定：整数量完全相等；浮点相对误差 ≤ 1e-9。若参照库口径不同（如 skimage 周长），先写明换算关系再比较。
3. **性质测试**：
   - 平移不变（面积、形状、距离）；
   - 左右翻转使左右量互换（A13、A19、A23）；
   - 缩放使面积按 k²、长度按 k 变化（整数倍上采样）；
   - spacing 换算与像素量一致。

### 2.9 跨工具一致性（不同模型对同一结构，作为 V5 补充）

在同一批图上比较：PSPNet 心影与 CXAS heart、PSPNet 肺与 CXAS lung、PSPNet 肺与 HybridGNet 肺轮廓，以及 A26 隆突与 CXAS tracheal bifurcation 的位置。只报告一致性分布，极端不一致的样本逐例查看，以排查回映或侧别错误。

## 5. 通过标准与结论格式

每个接口最终给出一行结论：

| 接口 | V1 | V2 | V3 | V4 | V5 | 变异自检 | 结论 |
|---|---|---|---|---|---|---|---|

- 全部适用项通过，结论记为“**实现验证通过**”。
- 任一项失败，记为“实现缺陷”，先修复再重跑全套。
- 缺参照数据而无法做的项标“不适用/缺参照”，并写原因，不能当作通过。

V5 的区间只用于发现实现错误，**不得写成准确性结论**。

## 6. 执行顺序（建议）

1. 冻结样本清单与全部容差、V5 区间（本方案确认后）。
2. V1 清单复核与 V2 独立参照、性质测试（确定性工具，不需要 GPU）。

5. V5 预期表现核对与 2.9 跨工具一致性。
6. 变异自检。
7. 汇总报告；结果同步到 `doc/项目现状.md`。

V3 A8 概率图最大绝对误差与病例分数使用冻结容差 `pneumothorax_prob_max_abs`；A26 四类线路 mask 的逐类及最小 IoU 使用冻结容差 `lines_tubes_line_iou`。这些协议数值由当前套件落实为通过断言，不能只在汇总里记录。

**本轮验证发现并已修复的实现缺陷（代码已改，148 项单测通过）：**

1. **A1–A4 PSPNet 预处理与官方不一致**：缩放方式与裁剪偏移都不同（偏移在宽高奇偶不同时差 1 像素）。已改为官方流程。所有旧 PSPNet 缓存（含 `trials/` 下的）因版本号变化而失效，这是预期行为。
2. **A14 旋转长宽比不唯一**：最小面积外接矩形存在并列时结果取决于 Shapely 的内部顺序。已改为自写旋转卡壳，并列时取最细长者，有单测。
3. **A25 旋转指数在锁骨内端越过脊柱中线时无意义**：可出现 −1.5 之类超出 [−1, 1] 的值。已改为报 `unknown` 并说明原因，有单测。
4. **CheXOne 选项概率取自后处理分数**：作者发布的 `generation_config` 带 `repetition_penalty=1.05`，会惩罚提示词中出现的选项字母。已改为取原始 logits 的 softmax；worker 同时输出 `token_ids` 供逐 token 比对。
5. **CheXOne worker 与模型卡流程不一致**：曾额外加入 system message、图片级 min/max 像素覆盖并强制贪心；已改为 user-only 消息、processor 只设 `max_pixels`、保留 checkpoint generation config。修复后同 GPU 对照为 221/240 token 序列一致，选项原始概率差为 0；剩余框输出差异尚未解释。

**发现但未改的事项（需在报告中写明）：**

- CheXOne 按模型卡 generation config 执行后仍有 19/240 个回答的框/未检出序列差异；官方流程重复运行 240/240 一致，差异不是采样随机性，需继续核对视觉 processor 输入细节。
