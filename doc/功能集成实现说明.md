# 功能集成实现说明

> 版本：v1.1（2026-11-02）
> 范围：`FunctionSpec`、依赖规划、规则/类别路由、三层证据图和统一功能执行入口。
> 本文描述软件实现状态，不报告医学准确率。

## 1. 当前交付

功能层不把 A1-A26 重新包装成 26 个孤立工具。每项 Q/P/T/S/G 功能是一份版本化证据程序：规格声明需要哪些 A 工具、怎样形成依赖闭包、什么情况拒答，以及最终关系和声明如何追溯到 A 工具观察。

| 交付 | 位置 | 当前状态 |
|---|---|---|
| `FunctionSpec` / `ToolStep` | `src/visevi/functions/specs.py` | 已实现并校验 |
| 26 份功能规格 | `src/visevi/functions/specs/*.json` | 已建立；评估协议均为 `draft_not_frozen` |
| 依赖图和规则路由 | `src/visevi/functions/planning.py` | 已实现 |
| 五类 Gate 网络与策略 | `src/visevi/vqa/gate_network.py`、`category_gate.py` | 五个独立线性/MLP 头、独立阈值与未训练保护已实现；编码器、训练与校准暂缓 |
| 类别到功能的可选适配 | `src/visevi/vqa/category_function_gate.py` | 在所选类别内规则匹配；多类别拒绝进入当前单功能 VQA，默认规则入口保留 |

“规格存在”只表示目标、工具依赖、输出、拒答和候选评估方案已经结构化。只有具备显式声明程序的功能才可以执行；只有完成冻结协议下的独立评估后，才能报告功能准确性。

## 2. FunctionSpec

每份 JSON 由 `FunctionSpec.from_dict()` 严格加载。加载器要求目录中恰好包含 Q1-Q4、P1-P12、T1-T4、S1-S3、G1-G3，并检查：

- 功能编号、类别、版本、输入类型和状态；
- `ToolStep` 的工具名、参数、必需/可选状态和上游步骤；
- 重复步骤、未知依赖和依赖环；
- 输出字段、槽位、适用条件、拒答规则和阻塞项；
- 独立参照、主次指标、数据划分、统计方法和协议状态。

规格中的 `$input.xxx` 是运行时输入引用。例如 G1 把 `$input.finding` 传给 `detect_abnormalities`。规格不保存运行目录或 GPU；执行器按本次 episode 注入这些工程参数。

26 份规格都经过 `build_a_registry()` 的真实接口菜单检查：工具名必须存在，固定参数必须符合工具的输入 schema，必需工具的依赖闭包必须完整。规格状态为 `specified`，不表示 `validated`。

## 3. 依赖图和路由

`DependencyGraph` 在任何工具运行前检查 DAG，然后提供稳定拓扑顺序和 required closure。一个可选步骤若是必需步骤的上游，也会进入必需闭包。注册表缺少必需工具时，episode 返回结构化拒答。

`RuleRouter` 是闭集路由器：

- 显式 `P9` 或 `['Q4', 'P9']` 可直接、可复现地路由；
- 自然语言只按规格中的登记关键词匹配；
- 多个关键词候选返回 `ambiguous`，不会猜测；
- 未知编号返回 `unknown`，不会回退到相似关键词。

VQA 可选择在类内规则路由之前注入五类 Gate：问题向量分别输入 Q/P/T/S/G 五个独立头，每个头输出一个启用 logit；独立 Sigmoid 与阈值决定类别集合。`CategoryFunctionGate` 只在唯一所选类别的目录内查找功能，多类别保留在 trace 中并拒绝当前单功能执行。单功能 runner 已允许 26 项功能进入完整证据卡/consumer/verifier 流程；没有已训练 Gate 权重时，默认仍使用规则 Gate。

当前没有问题编码器默认权重、已训练 Gate 或校准结果。部署接口默认返回 `untrained`，不会以随机参数执行 A 工具；默认 `RuleFunctionGate` 不变。网络前向保留梯度，标注路由或最终回答 loss 的训练选择暂缓。细节见[五类 Gate 网络调研与实现](五类Gate网络调研与实现.md)。需求解析与槽位抽取即使以后采用大模型，也只能提出 schema 化候选，不能跳过闭集目录或断言视觉事实。

## 4. 三层证据图

功能层复用原有 `EvidenceUnit` 和 `EvidenceSession` 序列化格式：

| 层 | 内容 | 示例 |
|---|---|---|
| Observation | A 工具或可信输入直接产生的事实 | 心影 mask、PA/AP、病灶候选框、已核实方向 |
| Relation | 对观察的确定性推导 | CTR、候选框与左右肺的重叠关系 |
| Claim | 面向功能命题的结构化声明 | 本次投照证据、带条件 CTR、候选侧别证据 |

派生节点必须引用已有上游节点，边必须有 `basis`。Claim 明确区分 `supports` 和 `contradicts`；节点不能同时支持并反对同一声明。图检查器还会发现缺失引用、伪造保留字段、非法边、自环和依赖环。模型缓存等图外来源只能使用明确的 `cached:`、`artifact:` 或 `tool_call:` 前缀。

## 5. run_function_episode

入口支持显式功能编号、规则查询、已有会话、注入注册表、运行时输入、工具参数覆盖、模型设备和新输出目录。典型调用为：

```python
from visevi.functions import run_function_episode

result = run_function_episode(
    "Q4",
    image_ref="/absolute/path/image.png",
    out_dir="/absolute/path/runs/q4-case-001",
    device="cuda:4",
)

print(result.status)
print(result.functions[0].outputs)
```

G1 需要给出冻结词表中的 finding：

```python
result = run_function_episode(
    "G1",
    image_ref="/absolute/path/image.png",
    inputs={"finding": "nodule"},
    out_dir="/absolute/path/runs/g1-case-001",
    device="cuda:4",
)
```

默认只输出图像侧。需要患者侧时，调用者还必须传入 `orientation_verified=True`、`patient_right_is_image_left` 和可审计的 `orientation_source`；执行器会把这项可信输入写成 Observation。任意非空字符串本身不能证明方向已核实，调用方必须按数据协议提供真实来源记录。

`out_dir` 必须是新目录，避免覆盖旧结果。成功运行会保存 `session.json` 和 `episode.json`。同一内存会话中，执行器按注册表实例、图像哈希、工具参数和输入 mask 内容复用成功观察；参数或 mask 改变会使缓存失效。复用模型观察时保留首次运行的 artifact 路径和参数，旧运行目录因此是重放记录的一部分，不能删除。

## 6. 已注册功能的边界

### Q4 投照

Q4 调用 A24 `classify_view`，保留 PA、AP、lateral 和 unparsed。原始选项分数明确标为未校准，不会改写成临床概率。解析失败时拒答。

### P9 心影大小/CTR

P9 的必需链是 A24 投照、A25 原始质量量、A2 心影和 A12 自动 CTR。只有 PA、质量量完整、相关结构未触边、心影未被模型视野截断、宽度为正且 CTR 与分量一致时，才产生带条件的测量声明。

当前输出是原始 `CTR` 比值及投照/质量条件。`enlargement=None` 且 `clinical_interpretation=not_assessed`：临床阈值、质量分级和校准映射尚未冻结，系统不会仅凭一个比值声称心影增大。

### P3 结节/肿块

P3 仅接受冻结词表中的 `nodule` 或 `mass`。它把 A6 候选框绑定成对应的 `Candidate_<finding>` mask，再用 A9、A14 和 A20 计算框中心、框宽高、框并集形状及肺区。候选未检出、输出无法解析、mask 与 A6 观察不绑定或候选完全位于肺外时拒答。

这些几何量描述的是模型候选框，不是病灶轮廓；像素宽高也不是物理直径。独立评估必须分别标注候选框/中心和真实病灶尺寸，不能用框宽高冒充肿瘤大小。

### P6 气胸

P6 保留 A8 分割/病例原始分数和 A6 语义候选两个独立检测通道，并把 A19 肺镜像相似度作为解剖上下文。程序显式输出 `concordant_positive`、`concordant_no_region`、`discordant_a8_positive` 或 `discordant_a6_positive`，不会把两个未校准分数融合成概率。

A19 不提供气胸侧别，也不能证明疾病不存在。A8 mask 的面积、边界框、尺寸、owner 和阈值状态必须彼此一致；独立医学评估仍受 A8 训练来源未知和独立分割参照缺失阻塞。

### T1 气管插管

T1 只调用 A26，在 A26 断言 ETT 存在且尖端、隆突均有效时，直接计算两个点之间的欧氏距离和有符号垂直距离。ETT 线路 mask 仅用于溯源，不会代替尖端点；原始存在/位置分数保留为未校准输出。

当前单位只有像素。由于可信像素间距和临床位置阈值尚未冻结，程序不换算厘米，也不声明“合适”“过深”或“过浅”。

### T2 中心静脉导管

T2 调用 A26 的 CVC 线和模型远端点；调用者必须额外提供一个带来源、原图坐标系和当前图像 SHA256 的目标点。程序直接计算 CVC 远端点到该目标点的像素距离，并保留未校准的存在分数。整块纵隔不会被当作腔静脉-右心房交界目标，也不会输出临床位置分级。缺少目标点、目标点错帧、CVC 未检出、线路不完整或远端点无效时拒答。

### T3 鼻胃管

T3 调用 A26 的 NGT 线路和最低可见端点；调用者必须提供带来源和图像绑定的膈面投影折线。程序判断线路是否跨过该折线，并明确标记 A26 端点只是最低可见点，不能当作真实尖端。结果是二维投影穿越证据，不是胃内位置或临床适合性判断。缺少膈面折线、错帧、线路不完整或没有交叠的参考横向范围时拒答。

### T4 胸腔引流管

当前公开可核实的相关研究主要提供引流管尖端框，未提供可直接下载的路径、侧孔模型、权重或数据；本地 Chest ImaGenome 也只有少量弱框/关系标注。因此 T4 先实现为显式 caller-reference adapter：调用者提供带来源、原图坐标系、图像 SHA256 的引流管路径 mask、尖端和侧孔坐标；程序验证坐标与 mask 一致，并计算引流管与左右肺的二维投影关系。缺少该 reference 时直接拒答；这不代表自动检测器已经实现，也不把 A26 无输出解释成无引流管。

### G1 左右定位

G1 调用 A1 肺野、A6 冻结 finding 候选和两次 A21 空间关系。候选 mask 必须绑定本次 A6 观察，并分别与 Right_Lung、Left_Lung 计算重叠。未核实图像方向时只给 `image_left` / `image_right`；核实后才能映射患者侧。

A6 返回 `not_detected` 时没有可定位对象，G1 结构化拒答且不生成 Claim。这个结果不能被解释为疾病不存在。候选框是框并集，不是病灶分割；双侧结果也不能自动表示每个病灶各自位于哪一侧。

### G2 肺区定位

G2 组合 A1 肺分割、A6 候选框和 A20 三等分肺区。程序核对肺 mask、候选 mask、A20 输入快照及 observation owner；仅在方向来源明确且 `orientation_verified=true` 时输出患者侧，否则只输出 `image_left`/`image_right`。区域按每侧肺纵向范围分成上、中、下三等分；候选可跨区，按各区像素重叠保留，不强制单一区域。该划分不是肺叶解剖。候选未检出、mask 截断或 A20 输入绑定不一致时拒答。

### G3 二维空间关系

G3 组合 A1-A3 解剖 mask、A21 单对关系和 A22 多区域关系。调用者提供的病灶 mask 必须带 observation owner、来源说明、原图坐标系和当前图像 SHA256；自动生成的解剖区域必须绑定本次分割 observation。程序核对 A21/A22 的输入参数、mask 哈希、来源快照和所有区域对。输出只表示二维投影像素单元的重叠、包含、相邻、分离和距离，不把它解释成三维遮挡、侵袭或因果关系。没有独立关系标注时仅用于合成软件验证和工程流程检查。

### S1 随访变化

S1 使用两个独立 `EvidenceSession` 运行 prior/current 的 A6 候选、A9 框范围和 A15 显示灰度统计，避免跨图像复用预测缓存。prior 观察以独立命名空间导入聚合证据图；保存结果时同时写出 current、prior 会话和各自图像哈希。

当前试点不自动做配准或病灶匹配。调用方必须提供同一患者的 `sha256:<64 位小写十六进制>` 哈希标识、不同 study ID、严格时间顺序、可比投照、已应用到两个输入的可信配准、已核实的一对一病灶对应，以及公共像素坐标系；两图尺寸也必须相同。程序只报告 prior/current 候选框宽高与显示灰度均值及其差值，`change_direction=not_assessed`，不会声明吸收、进展或稳定。无效成对元数据会在程序 trace 中整体脱敏，不会把误传的明文患者标识写入结果文件。

## 7. 状态和失败语义

| 状态 | 含义 |
|---|---|
| `ok` | 所选功能均形成有效声明 |
| `partial` | 多功能 episode 中部分成功、部分失败或未实现 |
| `refused` | 必需输入/证据缺失、工具拒答、输出非法或适用条件不满足 |
| `blocked` | 规格存在，但功能声明程序尚未实现 |
| `ambiguous` | 查询匹配多个功能，需明确编号 |
| `unknown` | 功能不在闭集目录中 |

工具异常由注册表转为 `ToolRefusal`。非法工具输出会回滚该次调用对节点、mask 和 landmark 的修改，调用轨迹仍保留用于审计。可选工具失败只进入缺失清单；必需工具失败立即停止对应功能。

## 8. 软件验证和下一步

软件验证覆盖规格完整性、真实注册表参数、DAG、规则路由、五类 Gate、三层图约束、必需/可选拒答、Q/P 程序、T/G/S 组合、JSON 保存和旧结果保护。最新测试结果见[项目现状](项目现状.md)。Q/P 单图及 400 图开发集流程已运行；G2/G3、S2/S3、T2/T3、T4 主要完成合成集成测试。上述结果用于软件组合核对，医学准确性仍按独立协议评估。

下一步按依赖推进：

1. 在已有 Q4 EvidenceCard、consumer 和 verifier 上完成图文联合输入对照；
2. 明确证据冲突、来源去重和充分性协议；情境折扣与校准另行冻结；
3. 接入 P9 VQA 并核对人工 CTR 口径，补齐数值、单位、适用条件和引用核验；
4. 分别运行 Oracle 组合、预测组合、反事实干预和消费大模型评估；
5. 为 T4 选定支持胸腔引流管、侧孔和尖端的自动后端；在后端确定前保留 reference adapter，并把自动模型缺失写入评估限制。
