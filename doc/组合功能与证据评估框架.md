## 1. 项目定位

本项目不是把 A1–A26 当作 26 个互相独立的最终产品。A 工具是视觉证据的基础元件：它们分别产生肺野、心影、关键点、病灶框、灰度、纹理、距离、投照、设备线路等局部事实。业务功能则由多个元件经过明确的组合程序得到。

项目中的五类业务功能是：

| 类别 | 编号 | 含义 |
|---|---|---|
| Q | Q1–Q4 | 图像质量和投照条件 |
| P | P1–P12 | 病理征象与测量 |
| T | T1–T4 | 导管和设备定位 |
| S | S1–S3 | 前后检查的随访变化 |
| G | G1–G3 | 左右、肺区和空间关系 |

E 类组合暂不作为当前阶段的依赖。当前 A1–A26 已有正式接口和首轮工程核验记录，但实现验证总门尚未关闭；还没有独立医学准确性结果，也还没有完成 26 项组合功能的正式评估。

必须区分四种状态：

1. **接口存在**：工具能被注册表发现，并有明确输入输出。
2. **工程正确**：坐标、单位、缓存、解析、确定性计算和拒答行为通过首轮测试；完整实现验证还要继续对照作者官方流程、预处理和预期表现。
3. **工具准确**：模型输出与独立人工参照或可信独立数据比较后达到预先冻结的指标要求。
4. **功能准确**：多个工具组合后的证据声明与独立功能参照一致，并且拒答、冲突和适用条件都正确。

接口与工程正确性已有首轮成果，但 A 工具实现验证仍有未通过项。组合程序开发可并行；独立医学准确性结论必须等待相应参照和冻结协议。

## 2. 为什么需要组合功能

单个工具通常只能回答一个局部问题。例如：

- A2 可以给出心影 mask，但不能判断这张片是否适合直接解释心胸比。
- A12 可以给出 CTR，但它依赖 A2 的心影和 CXAS 的肋骨内缘，也需要投照条件和图像质量作为解释条件。
- A6 可以给出“心影增大”的候选框，但候选框不是心胸比测量，也不能单独替代定量测量。
- A19 可以计算肺野镜像相似度，但它不能自动证明病灶是左右对称分布。

因此，最终功能必须表达：

```text
目标问题
  → 需要哪些证据槽位
  → 哪些 A 工具填充这些槽位
  → 哪些关系或测量由证据推导
  → 哪些条件会降低可信度
  → 哪些冲突会导致拒答
  → 形成什么样的证据声明
```

组合功能不是把几个工具的自由文本拼接起来，而是一个有类型、有依赖、有适用条件、有拒答规则、可重放的证据程序。

## 3. 总体流水线

端到端流程固定为：

```text
用户问题 / 检查任务
        │
        ▼
需求解析：识别 Q/P/T/S/G 与功能槽位
        │
        ▼
FunctionSpec：编译必需工具、可选工具、依赖和拒答规则
        │
        ▼
A 工具层：生成 mask、点、框、属性、测量和质量元数据
        │
        ▼
证据标准化：统一原图像素坐标、单位、状态和 provenance
        │
        ▼
关系与测量层：距离、CTR、空间关系、双侧分布、前后变化
        │
        ▼
证据组合层：来源去重、情境折扣、冲突和充分性判断
        │
        ▼
EvidenceGraph：观察、关系、声明以及支持/反对/溯源边
        │
        ▼
EvidenceCard：确定性渲染的证据卷宗
        │
        ▼
消费大模型：根据声明编号和适用条件作答
        │
        ▼
确定性核验器：检查引用、方向、数值、单位和拒答规则
```

系统中心仍然是 `EvidenceSession`。它保存需求、证据图、工具调用轨迹、程序轨迹和最终判定；模型后端、组合规则和消费模型都不能绕过这个会话对象自行保存不可追踪的结论。

## 4. 五类 26 项功能

下面按当前 `FunctionSpec` 与组合程序说明各类功能。数据协议、独立参照和指标在[未来计划](未来计划.md)中维护。

### 4.1 Q 类：质量和投照

| 功能 | 主要 A 组合 | 组合输出 | 主要参照 |
|---|---|---|---|
| Q1 吸气程度 | A5 + A25 | 肺底、膈顶、肋骨计数、吸气相关原始量和适用条件 | 专家等级、人工肋计数和膈顶 |
| Q2 体位旋转 | A4 + A9/A11 + A25 | 锁骨–脊柱关系、旋转量、旋转状态 | 人工端点距离和专家等级 |
| Q3 曝光/对比度 | A15 + A17 + A25 | 灰度、清晰度、心后透亮度等原始质量量 | 技术质量或心后可见度等级 |
| Q4 PA/AP | A24 | PA、AP、lateral、unknown、原始回答和状态 | 独立 ViewPosition 加人工复核 |

Q 类证据是**元证据**。它通常不直接投票决定病理命题，而是影响其他通道的适用性和不确定度。例如 AP 投照会降低 CTR 解释的可信度，旋转会降低左右对称性解释的可信度，视野截断会使相关测量直接拒答。

### 4.2 P 类：病理征象

| 功能 | 主要 A 组合 | 组合输出 | 主要参照 |
|---|---|---|---|
| P1 实变/渗出 | A6/A7 + A15/A16 + A18 | 病例证据、候选区域和外观支持 | 病例标签与病灶框 |
| P2 间质改变 | A6/A7 + A16 + A18 | 冻结后的单一表型、区域或病例证据 | 对应表型标签和区域参照 |
| P3 结节/肿块 | A6/A7 + A14 + A20 | 框、中心、大小和肺区 | 框、中心、大小和肺区标注 |
| P4 肺气肿/过度充气 | A5 + A15 + A25 | 膈顶和肋骨几何量、外观和病例证据 | 疾病标签、膈顶和人工分度 |
| P5 胸腔积液 | A5 + A6/A7 + A15/A17 | 肋膈角、候选框和外观证据 | 病例标签和角点参照 |
| P6 气胸 | A8 + A6/A7 + A19 | 气胸 mask、病例分数、语义候选和冲突 | mask 与病例标签分开评估 |
| P7 纵隔宽度 | A3 + A9/A11 | 纵隔边界、宽度和距离 | 人工边界和宽度 |
| P8 肺门增大/增浓 | A15/A16 + A23 + 已登记的肺门结构 | 肺门 ROI、双侧分布和等级证据 | 肺门 ROI 与专家等级 |
| P9 心影大小/CTR | A2 + A12 + A24 + A25 | CTR、投照/质量条件和心影增大证据 | 人工心影及胸廓内缘端点 |
| P10 主动脉结 | A9/A15 + 已登记的主动脉结构 | 宽度、灰度和钙化候选 | 人工结部测量、突出等级和钙化标签 |
| P11 骨折 | A4 + A6/A7 + A17 | 骨折候选框和局部外观证据 | 骨折框和病例标签 |
| P12 皮下气肿 | A15 + A18 + A21/A22 | 病例、区域和空间关系证据 | 病例标签和区域标注 |

P 类中“病例检出”和“区域定位”必须分开报告。一个工具可以病例级判断正确，却给出错误位置；也可能框位置接近，但病例级分数没有达到工作点。

### 4.3 T 类：导管和设备

| 功能 | 主要 A 组合 | 组合输出 | 主要参照 |
|---|---|---|---|
| T1 气管插管 | A26 ETT + A26 隆突 + A11 | 设备存在、尖端、隆突和尖端到隆突距离 | 设备线、尖端和隆突标注 |
| T2 中心静脉导管 | A26 CVC + A11 + 结构参照 | 设备存在、尖端和目标位置关系 | 尖端及目标解剖标注 |
| T3 鼻胃管 | A26 NGT + A5 + A11 | 线路、可见末端、过膈状态和距离 | 路径、过膈和尖端标注 |
| T4 胸腔引流管 | A26 扩展后端 + A1–A4 | 管体、侧孔、尖端和胸膜腔关系 | 管体、侧孔和尖端标注 |

当前 A26 后端不覆盖胸腔引流管，因此 T4 不能因为已有 `localize_devices` 接口就视为完成。

### 4.4 S 类：随访变化

| 功能 | 主要 A 组合 | 组合输出 | 主要参照 |
|---|---|---|---|
| S1 吸收/进展 | 前后 A1/A2/A6 + 配准/病灶匹配 + A9/A15 | 变化量、变化方向和对应病灶 | 同患者序列与变化方向 |
| S2 新发病灶 | 前后 A1/A2/A6 + 时间匹配 | 新发候选及时间证据 | 前后病灶对应和新发标签 |
| S3 稳定性 | 前后 A1/A2/A6 + 变化规则 | 稳定、变化或不确定 | 人工稳定/变化标签 |

S 类不能用两张互不相关的图像模拟随访。正式评估需要同一患者、可确认时间顺序的成对检查；在真实成对数据到位前，只能用合成元件验证配准和变化程序。

### 4.5 G 类：左右、肺区和空间关系

| 功能 | 主要 A 组合 | 组合输出 | 主要参照 |
|---|---|---|---|
| G1 左右定位 | A1 + A6/A7 | 图像侧、患者侧和侧别溯源 | 独立病灶侧别标签 |
| G2 肺野/肺区定位 | A1 + A20 + A6/A7 | 左右肺、上中下区和命中关系 | 独立区域标签 |
| G3 遮挡/空间关系 | A21 + A22 + A1–A4 | 二维重叠、包含、邻接、距离和关系状态 | 明确限定为二维投影关系的人工标注 |

G3 的默认输出是二维投影关系。像素重叠不能自动解释为三维遮挡，除非另有明确的语义标注和协议。

## 5. `FunctionSpec`：把功能写成可执行协议

每个功能必须有一份版本化的 `FunctionSpec`。它不是说明性文字，而是可以被路由器、规划器、评估器和报告器读取的协议。

### 5.1 最小字段

| 字段 | 作用 |
|---|---|
| `function_id` | 如 `P9`、`G1` |
| `category` | Q/P/T/S/G |
| `proposition` | 功能要回答的证据命题 |
| `input_type` | 单图、成对图或时间序列 |
| `required_tools` | 必须执行的 A 工具 |
| `optional_tools` | 用于补充或仲裁的工具 |
| `slots` | finding、location、measurement、device、comparison、condition 等槽位 |
| `dependency_graph` | 工具和关系的执行顺序 |
| `outputs` | 结构化输出字段和单位 |
| `guards` | 运行前的适用条件检查 |
| `refusal_rules` | 缺失、冲突、截断和不适用时的拒答规则 |
| `reference` | 独立参照来源和标注规范 |
| `metrics` | 主指标、次指标和统计方法 |
| `split` | 开发、校准和测试划分 |
| `version` | 协议版本和冻结日期 |

### 5.2 P9 示例

```yaml
function_id: P9
category: P
proposition: cardiomegaly_evidence
input_type: single_image
required_tools:
  - segment_heart       # A2
  - measure_ctr         # A12
  - classify_view       # A24
optional_tools:
  - assess_image_quality # A25
slots:
  - measurement: CTR
  - condition: projection
  - condition: image_quality
dependency_graph:
  - segment_heart -> measure_ctr
  - classify_view -> projection_guard
  - assess_image_quality -> quality_guard
guards:
  - view must be PA for the primary clinical interpretation
  - heart mask and rib masks must be complete
  - CTR must be returned with a valid thoracic inner margin
outputs:
  - ctr
  - projection
  - quality_conditions
  - evidence_claim
refusal_rules:
  - refuse when the required mask is missing or truncated
  - refuse clinical enlargement interpretation for AP unless explicitly requested
reference:
  type: blinded_manual_endpoints
metrics:
  primary: CTR_MAE
  secondary: Bland_Altman_limits, ICC, enlargement_AUROC
version: P9-v1
```

P9 的 `measure_ctr` 输出是一个测量节点；它还不是最终的“心脏增大”结论。组合程序要把 CTR、投照和质量条件组织成证据声明，声明中必须保留 A2、A12、A24、A25 的来源。

## 6. 证据图和证据类型

### 6.1 三层节点

| 节点层 | 内容 | 示例 |
|---|---|---|
| Observation | A 工具直接产生的事实 | Heart mask、肺尖点、病灶框、AP/PA、原始属性回答 |
| Relation / Measurement | 对多个元件的确定性推导 | CTR、左右面积差、病灶与肺野关系、尖端到隆突距离 |
| EvidenceClaim | 面向功能命题的综合声明 | “存在支持心影增大的证据”或“证据不足” |

当前 `EvidenceUnit` 已支持 `region`、`landmark`、`measurement`、`attribute`、`appearance`、`distribution`、`global_condition` 等类型。组合层应继续使用这些类型，而不是把所有结果重新转成自由文本。

### 6.2 节点和边必须可追溯

每个节点至少保留：

- `source_tool`：产生节点的 A 工具或组合程序；
- `value`：数值、类别、框、点、mask 摘要和状态；
- `region`：原图像素坐标中的空间范围；
- `provenance`：上游观察节点或工具调用；
- `validity_conditions`：单位、投照、视野、训练来源和适用条件；
- `confidence` 或原始分数：明确区分校准概率与未校准分数。

证据图的边必须带依据：

| 边 | 含义 |
|---|---|
| `supports` | 一个节点支持另一个声明 |
| `contradicts` | 两个来源对同一命题方向相反 |
| `attribute_of` | 属性属于某个区域或对象 |
| `spatial` | 两个区域存在二维空间关系 |
| `comparison` | 前后或左右比较 |
| `temporal` | 成对检查的时间顺序 |

### 6.3 相关来源不能重复计数

证据的数量不等于证据的独立性。组合前必须沿 provenance 图寻找共享上游：

- A1–A4 共享 PSPNet 预测，不能视为四个独立模型来源。
- A2、A9、A12 若共享 Heart mask，不能把同一心影误差重复计数。
- A6、A7、A18、A24 共享 CheXOne，不能简单当作四个独立语义来源。
- P9 中 A2/A12 的心影部分和 A12 的 CXAS 肋骨部分应分别记录。

来源去重之后，才进入跨来源的证据组合。共享来源可以产生多个互补字段，但不能因为字段数量多就自动提高支持度。

## 7. 证据组合和拒答

### 7.1 元证据与对象证据

Q 类功能和工具自身的有效性信号属于元证据：吸气、旋转、曝光、投照、视野截断、左右肺重叠、解析失败、点在图外等。它们主要用于调整其他证据的适用性。

P、T 类通常产生对象证据；G 类在对象证据之上建立空间关系；S 类在两次检查的对象证据之间做比较。

单一通道功能可以只有一个主要来源，但必须扩大无知区间并写明限制。需要综合判断的功能优先使用两类或更多互补通道，例如 P9 同时使用定量 CTR、投照和质量条件，必要时再加入语义候选。

### 7.2 保守的证据代数

对一个命题框架 `Θ={存在, 不存在}`，每个通道映射为质量函数：

```text
m(存在)       支持存在的质量
m(不存在)     支持不存在的质量
m(Θ)          尚不能区分的无知质量
```

报告时使用：

- `Bel`：对命题的支持下界；
- `Pl`：命题仍未被排除的上界；
- `Pl - Bel`：无知区间宽度；
- `K`：不同来源之间的冲突质量。

工具原始分数不是自动校准概率。校准映射只能在开发/校准集上拟合，不能在最终测试集上调参。当前阈值、校准函数和情境折扣参数都没有冻结。

### 7.3 情境折扣

情境折扣 `α` 表示某通道在当前条件下的可用程度：

- AP 投照时降低 CTR 解释通道的 `α`；
- 吸气不足时降低心胸比和膈顶相关解释的 `α`；
- 旋转明显时降低左右对称通道的 `α`；
- 视野截断时将相关测量通道的 `α` 置为 0，并拒答依赖该测量的功能。

折扣只增加无知，不应偷偷改变工具输出方向。每个 `α` 必须带可读的理由，并进入 EvidenceCard 的适用条件块。

### 7.4 停止和拒答

功能执行满足以下条件之一时停止：

1. **充分**：候选命题的支持区间已经足以区分竞争命题；
2. **冲突**：冲突超过开发集冻结的阈值，且没有可用的仲裁通道；
3. **不足**：候选工具已经耗尽，仍缺少必需槽位；
4. **不适用**：投照、视野、图像帧或数据类型不符合功能协议。

拒答是结构化结果，不是异常。必须记录拒答原因、缺少的节点、已经执行的工具和可补充的证据。

## 8. 如何选择使用哪个功能和工具

### 8.1 需求解析

当前路由先区分类别与功能：五个独立 Gate 各判断 Q/P/T/S/G 是否启用，输出可多选的类别集合；类内暂用规则选择 FunctionSpec。未配置已训练权重时部署接口返回 `untrained`，默认规则基线保留。没有通用槽位抽取器，标注路由监督或最终回答 loss 的训练方案暂缓。

未来问题解析器可以使用大模型，但输出必须是受 schema 约束的 JSON。例如：

```json
{
  "function_candidates": ["P9"],
  "finding": "cardiomegaly_evidence",
  "location": null,
  "needs_measurement": true,
  "needs_projection_condition": true,
  "input_type": "single_image"
}
```

解析结果只负责提出需求，不负责直接断言视觉事实。错误的功能路由要单独评估，不能混入 A 工具或组合算法准确率。

### 8.2 闭集路由和依赖闭包

类别确定后，功能路由器只能从对应的版本化子目录选择。当前 `CategoryFunctionGate` 只允许唯一类别进入单功能 VQA；多类别选择保留在 trace 中并拒绝执行，P9 及其他功能也不能绕过 runner 的 Q4 允许列表。

以下是通用规划器的目标步骤；当前执行器已具备 FunctionSpec 依赖闭包、拓扑执行和适用条件拒答，槽位覆盖求解、成本排序及充分性停止尚未通用实现：

1. 选出能够覆盖需求槽位的功能；
2. 展开必需 A 工具和关系计算的依赖闭包；
3. 检查图像类型、投照、视野和时间条件；
4. 按确定性计算、专用模型、VLM 的成本顺序安排执行；
5. 在证据充分、冲突或缺失时停止；
6. 把计划和实际执行轨迹写入 `EvidenceSession`。

小规模目录可研究精确的最小代价覆盖，类别 Gate 则独立保留可审计的分数、阈值和版本。Gate 的训练方式尚未确定，不将 RL 预先限定为只能作对照，也不在本阶段实现训练。

### 8.3 多功能问题

目标流程中，一个问题同时包含多个目标时，使用多个已登记功能组合。例如：

```text
“右肺病灶是否比前片进展，并且位于哪个肺区？”
    → S1（变化） + G1（左右） + G2（肺区）
```

多个功能共享同一 A 观察时，应只执行一次并在图中共享节点，不能制造虚假的独立证据。五类 Gate 已支持多类别输出，但现有 VQA 适配会拒绝执行该多类别结果；跨功能计划与最终答案聚合尚待实现。

## 9. 如何把证据送入大模型

### 9.1 EvidenceCard

大模型接收的是确定性渲染的 EvidenceCard，而不是一堆无序工具日志。卷宗建议按以下顺序：

1. 任务和输入图像信息；
2. 适用条件与元证据；
3. 编号化证据声明；
4. 支持、反对、冲突和缺失证据；
5. 可选的编号标记图；
6. 作答格式和引用合同。

示例：

```text
任务：判断是否存在心影增大相关证据

适用条件：
- 投照：PA，来源 [C4]
- 图像质量：可解释，来源 [C5]
- 视野截断：无

证据声明：
- [C1] CTR = 0.54，来源 A2+A12，单位为像素比例
- [C2] 心影增大候选框，来源 A6，框为候选区域，不是心脏分割
- [C3] 当前组合支持区间 [Bel, Pl] = [0.62, 0.81]，冲突 K = 0.05

限制：
- 心影和肋骨边界为模型预测，独立准确性尚未完成
- 结果为发现级证据，不是诊断
```

### 9.2 作答合同

消费模型必须遵守：

- 每个临床陈述都引用至少一个声明编号；
- 不能使用 EvidenceCard 中不存在的视觉事实；
- 数值和单位必须照抄声明；
- 不能把“证据不足”改写成肯定结论；
- 遇到冲突时必须说明冲突，不能静默平均；
- 如果声明要求拒答，模型只能返回证据不足或缺失证据。

建议模型返回结构化结果：

```json
{
  "answer": "存在支持心影增大的证据，但需要结合投照和临床情况解释。",
  "evidence_refs": ["C1", "C3"],
  "missing_evidence": [],
  "unsupported_claims": [],
  "abstain": false
}
```

### 9.3 确定性核验器

核验器检查：

1. 引用编号是否存在；
2. 引用的声明是否支持该句话的方向；
3. 数值、单位和类别是否与声明一致；
4. 是否出现没有证据引用的新增视觉断言；
5. 是否违反功能的适用条件或拒答条件。

第一次不通过时可以把具体错误反馈给模型重答一次；再次不通过就返回系统级 `AnswerVerdict(answerable=False)`。核验器失败本身要计入端到端评估。

## 10. 四条评估线

### 10.1 A 工具评估

评估单个预测工具与独立参照的关系：

- 分割：Dice、IoU、HD95、边界距离；
- 关键点：像素误差、归一化误差、语义点命中率；
- 框检测：FROC、AP、IoU、中心误差；
- 分类/属性：AUROC、AUPRC、macro-F1、灵敏度、特异度；
- 测量：MAE、偏差、Bland–Altman、ICC；
- 有序等级：加权 κ；
- 所有模型工具：覆盖率、拒答率、技术失败率。

如果没有独立 GT，只能报告工程正确性和“准确性未验证”，不能把模型开发输出当 GT。

### 10.2 B 组合功能评估

评估证据程序是否正确：

- 病例命题：用组合后的 BetP 或保守区间评 AUROC/AUPRC、ECE；
- 连续测量：评 MAE、偏差、Bland–Altman、ICC；
- 区域和关系：评 IoU、命中率、macro-F1、结构精确匹配率；
- 选择性预测：把区间宽度或拒答状态作为不确定度，报告风险–覆盖曲线和 AURC；
- 组合质量：报告冲突率、充分率、缺失率和拒答率。

### 10.3 C 大模型消费评估

在同一图像、同一问题和同一冻结证据下，比较：

1. 只给图像；
2. 图像加原始工具输出文本；
3. 图像加硬门控测量；
4. 图像加 EvidenceCard；
5. EvidenceCard 加或不加编号标记图。

每组至少使用三类消费模型时，报告最终答案准确率、覆盖率、引用精确率、引用召回率、核验通过率和数值抄录错误率。外部问答数据必须先核实许可和训练重叠，也可以先用本地标签模板生成可审计问答。

### 10.4 D 证据依赖和反事实评估

这是验证“模型是否真的使用证据”的关键实验：

- 删除一个必需声明；
- 翻转一个声明的方向；
- 交换左右肺；
- 缩小或扩大心影 mask；
- 删除肋骨或投照条件；
- 注入两个来源相反的声明；
- 注入多余但无关的声明。

主要指标：

- **证据依从率**：证据改变后，回答是否按预期改变；
- **恰当拒答率**：证据不足或冲突时是否拒答；
- **静默答错率**：错误证据进入后仍给出肯定错误结论的比例；
- **冲突识别率**：能否指出互相矛盾的声明；
- **通道边际贡献**：删除一个通道后 B 层指标和校准的变化。

这条评估线不需要额外临床数据，可以在已冻结的证据接口上做程序化干预。

## 11. P9 心胸比示例

P9 是首个完整示例，因为它同时包含分割、几何测量、投照条件、质量条件和最终大模型消费。

### 11.1 执行过程

```text
A2 segment_heart
    └── Heart mask

A24 classify_view
    └── PA / AP / lateral / unknown

A25 assess_image_quality
    └── 吸气、旋转、穿透和视野条件

A12 measure_ctr
    ├── A2 Heart mask
    └── CXAS 肋骨内缘

组合程序
    ├── 检查投照和视野条件
    ├── 检查 CTR 的心界和胸廓内缘
    ├── 按来源去重
    ├── 对 AP、吸气不足或旋转进行情境折扣
    ├── 生成 CTR 和心影增大证据声明
    └── EvidenceCard + 引用核验
```

### 11.2 四条评估线如何落地

1. **Oracle 组合**：给定人工心影和人工胸廓内缘，确认 CTR 公式、边界和拒答逻辑。
2. **预测组合**：使用 A2 和 A12 真实输出，测 CTR 与人工端点的 MAE、偏差和一致性。
3. **功能证据**：加入 A24/A25，比较 PA 与 AP、正常与低吸气、旋转与非旋转样本的覆盖率和证据区间。
4. **消费模型**：把同一 P9 EvidenceCard 交给多个模型，检查引用、数值和拒答。

### 11.3 消融

至少比较：

- A2 单独；
- A2 + A12；
- A2 + A12 + A24；
- A2 + A12 + A24 + A25；
- 去掉来源去重；
- 去掉情境折扣；
- 注入 CTR 与语义框冲突。

这样才能知道准确性变化来自新的互补证据、质量条件、来源去重还是纯粹的模型波动。

## 12. 数据和独立性原则

正式评估必须按患者或检查分组。精确像素去重只能排除最简单的泄漏，不能证明患者独立，也不能排除模型训练重叠。

当前主要限制：

- PSPNet 来源于 ChestX-Det，ChestX-Det 和同源 NIH 不能作为其独立测试；
- HybridGNet 的作者关键点训练来源包含 JSRT、Montgomery 等，不能用这些来源评估 A5；
- CheXOne 的训练来源包含 NIH、NLM-TB 等，本地 NIH、Montgomery 不能作为其独立语义测试；
- A8 训练来源没有充分公开记录；
- A26 训练包含 NIH，本地没有独立设备端点标注；
- S1–S3 需要同患者成对影像，目前本地数据不足。

每个测试样本都要保存：图像 ID、患者/检查分组依据、标注来源、适用条件、工具版本、权重哈希、配置、预测、中间节点、拒答原因和最终指标。

拒答必须保留在总分母中，至少同时报告：

```text
coverage = 成功返回功能结果的样本数 / 全部样本数
refusal_rate = 结构化拒答样本数 / 全部样本数
technical_failure_rate = 技术失败样本数 / 全部样本数
accuracy_on_covered_cases = 成功样本中的准确性
risk_coverage_curve = 不同覆盖率下的错误风险
```
