# 项目介绍：MedVisEvi 胸片视觉证据工具

> 工作根目录：`/ssd/visual_reasoning/zym/MedVisEvi`。核心文档包括：本文（项目与接口约定）、[项目现状](项目现状.md)（当前实现与数据）、[A 工具矩阵](A工具详细说明与评估矩阵.md)、[方法框架](MedVisEvi方法框架.md)、[未来计划](未来计划.md)和[组合功能与证据评估框架](组合功能与证据评估框架.md)。更新规则见文末。

## 1. 项目目标

为胸片（CXR）构建一组**可调用、可复算、可追溯**的视觉证据工具，供多模态大模型、规则程序或研究者按需调用。项目包含基础工具层和功能组合层，两层的开发可并行：

1. **A 阶段**：按师兄给定的基础能力矩阵 A1–A26，逐项定义接口、实现并验证。A 编号是能力，不一定一一对应模型：分割、定位等用学习模型，面积、距离、形状、空间关系等用确定性算法。
2. **功能层**：将 A 工具按 `FunctionSpec` 组合成 26 项业务功能（Q1–Q4 质量、P1–P12 病理、T1–T4 管路、S1–S3 随访、G1–G3 定位）；正式准确性评估在协议和独立参照就绪后开展。

复合证据层 E1–E10 暂缓，不作为任何阶段的依赖。

**三类证据分开记录，互不替代：**

| 证据 | 回答的问题 | 典型手段 |
|---|---|---|
| 软件/算法正确性 | 代码是否按定义计算 | 手算合成例、边界/异常输入、真图逐步复算 |
| A 工具预测准确性 | 模型输出与独立人工参照是否一致 | 独立 GT 上的 Dice、关键点误差、检测 AP 等 |
| 业务功能准确性 | A 组合后的功能是否可靠 | 冻结协议后在患者级独立测试集上评估 |

工具能被正确调用，不等于预测准确；A 工具准确，也不等于组合功能准确。

## 2. 系统结构

```text
推理者（MLLM / 规则 / 人）
   │ describe_all() 读取工具菜单（JSON Schema）；run(name, session, **params) 调用
   ▼
ToolRegistry ── 统一调用协议；每次调用写入 session.trace（参数、耗时、结果 id 或拒答）
   │
EvidenceSession ── 系统中心：证据图（EvidenceUnit 节点）、运行轨迹、运行时 mask 缓存及来源元数据
   │
   ├─ perception/            A 工具：anatomy、geometry、appearance、landmarks.py、vlm.py、findings.py、structures.py
   ├─ functions/             26 份 FunctionSpec、依赖规划、Q/P/T/S/G 组合程序与统一 runner
   ├─ construction/evidence.py Observation/Relation/Claim 证据图；ds.py、teachers.py 为旧 E 层实现
   ├─ vqa/                   问题路由、五类 Gate、EvidenceCard、consumer、verifier 与 VQA runner
   ├─ backends/              模型后端客户端：权重/源码校验、隔离 worker 进程、绑定缓存
   ├─ workers/               隔离运行的模型 worker
   └─ eval/                  A 工具注册表和批处理入口
```

模型类工具（A5–A8、A12 自动、A18、A24–A26）在 `.venv-models` 的常驻子进程中推理，主进程通过一行一个 JSON 的协议通信，只接收原图坐标的结构化结果和带校验和的产物文件。每次结果写入调用方指定的 `output_dir`，与图像、权重、第三方源码、worker 代码、环境、参数、设备绑定；完全相同时复用，否则拒答，不覆盖。

- `build_a_registry()`：A1–A26 全部 27 个接口（A12 有自动 `measure_ctr` 与给定边界 `compute_ctr_from_borders` 两个），新工作一律用它；`a_capabilities(registry)` 列出编号到接口的对应。
- `build_registry()`：兼容旧脚本，26 个名字中混有旧 E/质量接口，**不能当作 A1–A26 已完成的证明**。
- 正常结果为 `list[EvidenceUnit]`；缺输入、非法参数、来源不可信、超出适用范围时返回结构化 `ToolRefusal`（`reason`、`missing`、`conditions`），不抛异常、不静默给值。

## 3. 关键约定

| 主题 | 约定 |
|---|---|
| 坐标 | 原图像素坐标，x=列、y=行，原点左上，y 向下。所有 mask/框/点都映射回原图。点（A5 关键点、A26 尖端/隆突）与 A12 边界用像素中心坐标（像素 i 覆盖 [i−0.5, i+0.5]）；框（A6/A7、`EvidenceUnit.region`）用边坐标（图像覆盖 [0, W]，像素 i 覆盖 [i, i+1)） |
| 像素口径 | 每个前景像素是以整数坐标为中心的单位正方形。bbox 宽高（含端点计数）、A9 Feret 长径（像素单元角点）、A14 形状、A11/A22 间隙距离统一用此口径；像素中心距离只作为显式命名的次要值（`pixel_center_distance_px`） |
| 单位 | 默认像素。只有调用方给出可信 `(row_spacing, column_spacing)` 才输出物理量，不从 PNG 推断毫米 |
| 患者左右 | PSPNet 的 `Right_*` 通道在标准正位显示的图像左侧（真图核验与胶片 “L” 标记一致）。外部数据集的 left/right 命名须逐一核实（见现状文档的 Montgomery 结论） |
| 有效视野 | PSPNet 只看中心正方形裁剪（边长 min(W,H)）。裁剪外是**未观测区域**，不是背景。mask 触到位于图内的裁剪边时记录 `fov_truncated_sides`，所有基于该 mask 的测量拒答。其余模型看整幅图（A5 居中补零成方，A8/A26/CXAS/CheXOne 整图缩放），不存在裁剪外区域 |
| 缓存绑定 | 读缓存（`masks_dir`）必须有 `cache_record.json`，并核对图像 SHA256、模型名、文档登记的权重 SHA256、预处理版本与帧参数，以及每张 mask 的校验和；任一缺失或不符即拒答。现场模式（`output_dir`）要求完整绑定逐字段相同 |
| 外部提供的 mask | 用 `session.attach_masks({name: mask}, {name: 来源元数据})` 显式附加，来源写清（如数据集多边形），不能冒充模型输出 |
| 置信度 | 没有校准概率时 `confidence=None`，不写固定常数。模型给出的分数一律以 `*_raw_score` / `option_raw_probabilities` 报告，注明未校准 |
| 模型输出状态 | 模型类工具区分 `ok/detected/present`、`not_detected`、`below_screening_threshold`、`outside_image`、`unparsed`、`unknown`；解析失败保留原文，不强行归类 |
| 二值 mask | 只接受 bool、0/1、0/255；概率图须上游按明确阈值转换 |
| 位深/方向 | 所有模型后端与旧曝光代理只接受 8 位显示栅格，高位深须先做有记录的窗宽窗位转换；EXIF 方向非恒等时拒答；A15–A17 保留原生灰度精度 |
| 溯源 | 测量结果的 `provenance` 指向**当前**附加 mask 的那次观测；输出含实现哈希、参数、输入 mask 哈希与来源 |

## 5. 环境与常用命令

环境：`.venv`（Python 3.12，PyTorch 2.7.1，TorchXRayVision 1.4.0，NumPy 1.26）运行主程序；`.venv-models`（同一基础解释器，另装 transformers 4.56.2、qwen-vl-utils 0.0.11、torch-geometric 2.8.1、albumentations 2.0.8、segmentation-models-pytorch 0.5.0 等，见 `tools/requirements-models.lock`）只由模型 worker 使用。两者都以 `--system-site-packages` 继承 `/ssd/conda-envs/revision-sam3` 的 torch/numpy 等，模型缓存绑定会记录这些版本。系统默认 Python 3.14 不要混用。

模型设备：工具参数 `device`（如 `'cuda:4'`），缺省取环境变量 `VISEVI_MODEL_DEVICE`，再缺省为 `cpu`。按约定使用 GPU 4–7。

```bash
cd /ssd/visual_reasoning/zym/MedVisEvi
# 软件测试（-p no:cacheprovider 避免在项目内写 .pytest_cache）
.venv/bin/python -m pytest -q -p no:cacheprovider
# 真图逐步核验：A1–A26 全部接口 + 独立复算 + 两张叠加图；--out 必须是新目录
.venv/bin/python scripts/verify_a_tools_stepwise.py --out trials/<新目录> --device cpu --model-device cuda:4
# 多来源冒烟：每个来源取若干张图跑全部接口，汇总状态/拒答
.venv/bin/python scripts/run_a_tools_multisource.py --out trials/<新目录> --per-source 3 --model-device cuda:5
# 获取/校验模型资产（已有 provenance.json 的后端会拒绝重复获取）
.venv/bin/python scripts/fetch_model_assets.py chexmask-u chexone lines-tubes pneumothorax cxas
```

调用示例：

```python
from pathlib import Path
from visevi.core.session import EvidenceSession
from visevi.core.units import ToolRefusal
from visevi.eval.runner import build_a_registry

image = Path('original_data/chestx-det/images/test/36212.png').resolve()
session = EvidenceSession(image_ref=str(image))
tools = build_a_registry()
# A1–A4 二选一：output_dir=现场推理（新目录或完全匹配的缓存）；masks_dir=已绑定缓存
result = tools.run('segment_heart', session, output_dir='trials/my_run/masks', device='cpu')
if isinstance(result, ToolRefusal):
    raise RuntimeError(result.reason)
area = tools.run('measure_region_area', session, mask_name='Heart')
print(area[0].value['area_px'])
# 模型类工具：每次给一个新的 output_dir（或与之完全匹配的旧缓存）
ctr = tools.run('measure_ctr', session, output_dir='trials/my_run/cxas', device='cuda:4')
view = tools.run('classify_view', session, output_dir='trials/my_run/chexone_view', device='cuda:4')
```

## 6. 文档维护规则

- 核心项目文档按主题维护：项目介绍、项目现状、A 工具详细说明与评估矩阵、方法框架、未来计划和组合功能评估框架；不另开重复的计划或状态文档。A 工具实现验证在独立工作目录 `tool_verification/` 进行，其 README 是该项工作的方案与结果摘要。机器生成的证据（测试输出、环境、哈希）放对应的 `trials/` 或 `tool_verification/runs/` 目录，由文档引用。
- 状态变化只写进[项目现状](项目现状.md)（矩阵 + 变更记录）；计划、协议、阈值讨论只写进[未来计划](未来计划.md)。
- A 状态只用：`未开始`、`实现中`、`工程验证通过`、`独立准确性待评`、`完整通过`、`阻塞`。没有独立 GT 的模型工具不能标“完整通过”。
- 报告结果须写清是本轮实测还是引用记录；不把开发样本、模型预测或同源规则产物当成独立真值。
