## 1. 一句话现状

A 阶段：**A1–A26 全部有正式接口**（`build_a_registry()` 27 个接口；A12 有自动 `measure_ctr` 与给定边界 `compute_ctr_from_borders`）。统一 runner 与 VQA Python API 已覆盖 26 项功能；S1–S3 支持成对影像，外部 ROI/reference 功能可传入预置 `EvidenceSession`。T4 仍是显式 caller-reference adapter，不是自动胸腔引流管模型。26 项评估协议仍为 draft，Q/P 400 张开发集聚合只反映流程覆盖与拒答；G2/G3、S2/S3、T2/T3、T4 的合成测试也只是工程验证。Q4 使用专用闭集 verifier；其他功能使用 `function-response-1`，只接受与 EvidenceCard 完全一致且绑定 Claim 的结构化输出。自然语言槽位抽取、多功能联合回答、通用冲突仲裁和真实 VLM 推理评估尚未完成。尚无任何 A 工具或组合功能的独立医学准确性结论；当前 A 工具实现验证仍有未通过项。

五类类别路由已实现：共享问题向量输入，Q/P/T/S/G 五个参数独立的小 Gate 默认使用二层 MLP（隐藏宽度 128），可切换线性结构；五个独立 Sigmoid 按各类阈值选择零个、一个或多个类别。`NeuralCategoryGate` 默认返回 `untrained`；问题编码器、Gate 权重、训练目标与校准方案均待定。类别内仍使用规则选择 FunctionSpec，默认 VQA 路由仍为 `RuleFunctionGate`。详见[五类 Gate 网络调研与实现](五类Gate网络调研与实现.md)。

### 3.1 模型工具实现边界

- **后端框架**（`src/visevi/backends/`、`src/visevi/workers/`）：worker 子进程常驻、一行一个 JSON；绑定缓存含图像 SHA256 与帧、逐文件权重哈希、第三方源码目录摘要、worker 代码哈希、模型环境（解释器、关键包版本、锁文件哈希）、参数、设备；身份不同即拒答，产物逐个校验和；worker 崩溃/超时/报错转为拒答。
- **工具基类**（`perception/model_tools.py`）：参数校验、原子提交（全部单元成功才写入会话）、mask 附加时记录生产者 `observation_id`、模型分数统一为未校准原始分。
- **安全**：所有 PyTorch 检查点以 `weights_only=True` 加载（CXAS 仅放行 `argparse.Namespace`）；工具都在隔离环境运行，主环境不导入模型栈。
- **修复的第三方问题**：CheXmask-U 发布配置在推理时随机采样隐变量（改为均值输出）；PyG 2.8 对作者子类生成的 `propagate` 模板不兼容（恢复通用实现）；CXAS 作者代码 `strict=False` 加载（改为严格加载）。
- **测试**：新增后端协议（缓存复用、任何身份变化或篡改即拒、worker 失败/崩溃）、CXAS 规则手算、模型工具转换与拒答、CheXOne 解析器等测试。

| A9 外接框宽度（像素计数）与 Feret（像素中心）口径不一，1×10 横条得 10 与 9 | Feret 改为像素单元角点口径（横条 √101，单像素 √2），与 bbox、A14、A22 一致 | 横条/单像素/各向异性 spacing 手算；真图 Qhull 独立复算 |

| 旧曝光代理把 16 位图截断成 8 位再套 8 位阈值 | 高位深输入拒答 | `test_quality.py` 新增 |

缓存兼容性由当前权重、预处理、适配器代码和图像绑定共同决定；历史缓存不能仅凭目录存在就作为现场模式 `output_dir` 复用。资产准备与真图运行入口见[项目介绍](项目介绍.md)和[工具验证说明](../tool_verification/README.md)，各次结果只写新的运行目录。

**残余风险**：视野截断标记只在预测 mask 触到裁剪边时触发；若真实器官延伸到视野外而预测恰好止于边内，无法从预测本身发现。评估时须同时检查 GT 在视野外的比例（见第 5 节 Montgomery）。

**Montgomery 专项结论（2026-10-29 实测，全部 138 例）：**

1. **左右命名是图像侧，不是患者侧。** `leftMask` 在 138/138 张图上位于图像左侧（标准正位显示下的患者右肺），`rightMask` 在图像右侧。PSPNet `Right_Lung` 也在图像左侧，因此评估时 **`leftMask` ↔ `Right_Lung`、`rightMask` ↔ `Left_Lung`**。按名字直接配对会得到接近 0 的 Dice。
2. **PSPNet 中心裁剪会丢掉部分 GT。** 图像为 4020×4892（97 张竖图）或 4892×4020（41 张横图）。**71/138** 张图的人工肺 mask 有像素落在中心正方形视野外，最多丢 9.8%（中位 0.03%）。评估须事先选定：只在视野内计分并报告丢失比例，或改用补边输入（属模型配置变更，需单独验证）。
3. **轮廓口径不同。** 官方 mask 排除心脏后方肺区，严重病变时含推断边界；与 PSPNet 肺野定义的差异须先量化，不能全算作模型误差。
4. 已知精确去重不代表患者独立；官方说明要求不外传数据并在发表时引用。

## 6. 现存问题与风险

1. **独立准确性为零**：A1–A26 没有任何一项在独立 GT 上评估。
2. **训练重叠**：PSPNet ↔ ChestX-Det/NIH；CheXmask-U ↔ JSRT/Montgomery；CheXOne ↔ NIH/Montgomery/SIIM/VinDr/MS-CXR 等；lines-and-tubes ↔ RANZCR/NIH；A8 未知；CXAS 不与任何真实胸片重叠。详见[未来计划](未来计划.md) 2.1。
3. **仍存缺口**：A8 权重来源不明；A26 不覆盖引流管/起搏器；A25 无人工质量参照与分级方案；A12/A25 依赖 CXAS 肋骨与膈的预测，未验证。
4. **能力矩阵未覆盖的结构**：PSPNet 的肺门、主动脉、膈面、脊柱、气管通道已能输出，但不属于 A1–A4 定义；业务功能 Q2/P8/P10/T1 需要它们时须先修订矩阵。
5. **许可**：CheXOne、CXAS、管线模型权重均为非商业/仅研究（用户已接受）；A8 无许可说明；PSPNet 权重许可未单列。
6. **环境依赖外部**：`.venv` 与 `.venv-models` 都以 system-site-packages 继承 `/ssd/conda-envs/revision-sam3`（torch 等来自该环境），对方改包会影响本项目；模型缓存绑定会记录版本变化并拒绝旧缓存。
7. **网络**：10-30 时 huggingface.co、Google Drive、GitHub 均可达，但带宽约 1–2 MB/s 且大文件下载会停滞；`scripts/fetch_model_assets.py` 会保留已核对的预取文件。
8. **开发样本污染**：ChestX-Det `36212.png`、开发 12 例（NIH 6、JSRT 3、ChestX-Det 3）已被反复查看，不能进入正式测试集。
