# VQA：图像、问题与工具证据的联合输入方案

> 日期：2026-11-02。性质：研究方案与实现状态记录。
> 主设置：问题 + 原图 + 与问题相关的结构化工具证据。
> 当前 runner 只执行 Q4；以下通用证据选择、冲突仲裁和实验对照仍待实现与验证。Q4 最小结构化回答契约已实现，不能等同于独立图像语义核验。

## 1. 核心决定

将原图作为视觉输入，把问题和工具证据作为有明确边界的文本输入，在同一次模型调用中共同提供。evidence_only 保留为消融对照，不作为研究主设置。图像不能先被一段描述替代，工具 Claim 也不是医学真值。

建议首版不训练新的视觉融合模块：复用本地 Qwen3-VL、Lingshu 和 MedGemma 的图文接口，先验证输入组织是否有用。联合输入是否优于纯图像或纯证据，必须由同样本对照决定，目前没有“确定最优”的实验依据。

重要限制：`visual_assessment` 是 consumer 自报状态。当前 verifier 会拒绝 `conflict`、`uncertain`、`not_assessed`（图像+证据模式）等非 `consistent` 状态，也拒绝把自由文本塞入 `limitations`；它不重新读取图像，不能验证模型是否正确发现冲突。模型误报 `consistent` 仍可能通过文字与 Claim 的一致性检查，因此视觉冲突检出能力必须用独立图像标签评估，原始模型输出也必须留存。

2026-11-01 曾修复 consumer 提示词构造并补图像传递回归。2026-11-02 按代码审查将 verifier 收紧为 `q4-response-2`，为每例持久化原始输出、解析/核验结果、最终响应、EvidenceCard/prompt 哈希和 consumer 配置；图像缺失改为结构化 `INPUT_IMAGE_NOT_FOUND` 拒答。独立 image-only Q4 baseline 已接入 evaluator：只给模型问题和原图，不运行功能/工具，不发送 EvidenceCard 或参考标签；答案直接按闭集标签计分。evaluator 另报告原始回答准确率、患者聚类 bootstrap 区间和完整逐例审计记录。持久化 episode/session 会移除图像路径和样本 ID，仅保留图像 SHA256；未显式指定 `out_dir` 时，工具执行临时工作区在回答生成时可用，并随 episode result 对象释放。当前全量 CPU 软件回归 498 passed；Q4 三种 VLM 尚未完成真实 VQA 推理评估。

## 5. 证据如何组织

### 5.1 双层表示

完整审计图保持无损：图像哈希、权重/模型身份、预处理、坐标转换、原始分数、工具参数和产物引用继续保存在本地。模型输入卡使用确定性选择和渲染，保存问题需要的 Claim 及其来源，不让另一个 LLM 先总结删改。两者通过节点 ID、卡片版本和内容哈希绑定。

模型可见卡至少包含：

| 字段组 | 内容与作用 |
|---|---|
| 身份 | function_id、卡片/渲染器版本、image_id、审计引用 |
| Observation | 节点 ID、结构/病灶、工具、值、区域、分数语义、有效性 |
| Relation | 节点 ID、rule_id、输入节点、计算结果、单位和计算口径 |
| Claim | 节点 ID、允许表达的命题、支持/反对节点和条件 |
| 限制 | 缺失工具、失败、截断、坐标/方向未核实、未知量和冲突 |
| 视觉产物 | 如有辅助图，记录 image_id、原图来源、ROI/变换和证据节点 |

不可将未校准分数称作“医学置信度”；同一模型产生的多个节点不能算成多份独立支持。

### 5.2 选择规则

从目标功能 Claim 出发，保留 Observation/Relation 的上游闭包；同时纳入与目标命题关联的反对、冲突和必需条件。单纯 provenance 遍历可能遗漏非祖先的冲突节点，后续选择器必须显式检查。

只提供当前问题所需子图，不把 26 个功能的全部结果一并发送。超出 token 预算时，不得静默截断数值、单位或条件；先删除非必要审计细节，仍超限则返回明确的输入限制状态。可做无损/紧凑卡对照，逐字段检查是否改变含义。

### 5.3 同一模型调用中的输入边界

    固定任务指令：工具结果是带来源的预测证据，可能有误；不得伪造数值和引用。
    [question] 原问题 [/question]
    [original_image img-0] 真正的 image content [/original_image]
    [tool_evidence] 确定性渲染的结构化证据卡 [/tool_evidence]
    [output_contract] 固定版本的回答 schema [/output_contract]

具体 role 和 content 排列通过各模型官方 processor/chat template 适配。上述区块说明逻辑边界，不承诺所有模型支持同一种 system role 或原生 tool role。图像和证据应绑定本次输入；文件名、参考答案和带真值的元数据不能进入模型上下文。

### 5.4 mask、框和辅助图

数值/类别/短属性用文本，框和关键点保留明确坐标及坐标系。大 mask 不展开成像素 JSON。确需观察区域时，将 ROI 或细轮廓图作为额外图像，始终保留未叠加原图。不能把全部 mask 覆盖在唯一原图上。

每张辅助图有唯一 ID，说明原图哈希、裁剪框、缩放/补边和坐标映射；不得把彩色 mask 误称为原始影像。多图输入支持和 token 成本需逐模型验证。

## 6. 模型视觉判断与工具证据的冲突

当前 Q4 使用的最小结构为 `q4-response-2`。它用一个枚举字段表达模型自报的视觉状态，不代表已完成独立冲突检测：

    {
      "schema_version": "q4-response-2",
      "answer": "PA",
      "citations": ["claim-view-1"],
      "limitations": [],
      "visual_assessment": "consistent"
    }

当前 schema 只接受注册的 `visual_assessment` 状态（`consistent`、`conflict`、`uncertain`、`not_assessed`）和两个限制代码（`image_quality_not_assessed`、`projection_metadata_not_used`）；自由文本限制和额外字段会拒绝。图像+证据模式要求模型输出 `consistent` 才会通过；纯证据模式要求 `not_assessed`。这些是结构化接口约束，不是语义关键字扫描，也不证明模型确实看到了或正确理解了图像。

`visual_observations` 若在未来加入，也只是模型声称观察到的内容，不能自动当成 A 工具已核验 Observation；同一次调用中，它也不独立于工具文字。如果需要未接触证据的视觉判断，必须先以问题+原图单独调用，冻结短观察，再在第二次调用给证据。两次调用的独立性和收益仍需实验。

| 情况 | 建议的确定性处理 |
|---|---|
| consumer 自报与 Claim 一致 | verifier 继续核对 Claim 引用和闭集答案；一致不等于真实正确 |
| consumer 自报冲突或不确定 | verifier 拒答；保留原始输出供独立评估，当前没有自动复核 |
| 工具没结果、模型认为能回答 | 严格工具支持模式拒答；视觉补充模式需另立协议和单独指标，标为 visual_only/unverified |
| 精确测量 | 只能引用有效测量链；模型不能凭视觉生成精确 CTR 或距离 |
| 视野、坐标、单位、适用条件失败 | 阻断相关测量 Claim；不能用语言模型意见修复几何证据 |
| 不同工具冲突 | 保留来源和共享模型关系，不投票伪装独立性；按冻结的复核/拒答规则处理 |

核验器可以证明 JSON/引用/数值/规则符合合同，不能单凭这些证明读片正确。`visual_assessment="consistent"` 是模型自报，不是独立核验；当前 contract 也没有 `conflicts=[]` 这样的完整冲突清单。

## 7. 两个功能示例

### 7.1 Q4：投照识别

输入“这是 PA 还是 AP？”、原图，以及 A24 的观察和 Claim。若工具给 PA，模型自报 `conflict` 或 `uncertain`，`q4-response-2` verifier 会拒答并保留原始输出；但它不会独立检查图像，也不能保证 consumer 没有把分歧误报为 `consistent`。不能因两者都输出 PA 就宣称图像核验成功。

Q4 的价值是检验路由、实际图像传入、证据引用和结构化自报冲突状态。因为答案被单一工具 Claim 强约束，光测最终标签难以证明多工具证据组织有贡献。应同时保存工具原始类别、VLM 原始输出/解析状态和核验后结果，并与独立参考逐一比较。

### 7.2 P9：心胸比

输入“心胸比是多少？”、原图、心影/胸廓测量依据、A12 结果、A24 投照及 A25 质量条件。后续可额外给出测量线辅助图，但保留原图。模型只能引用本次测量结果和条件，不得根据整体视觉印象替换数值。

P9 组合程序已实现，但 `SUPPORTED_VQA_FUNCTIONS` 当前只开放 Q4，因此 P9 尚未接入 VQA runner。若仅有模型分割却无独立参考，可验证链路和数值转述；连续测量准确性仍需同口径人工测量。投照或测量条件不满足时，明确限制或拒答；不将一个几何比值自动改写成临床诊断。此处仍是后续组织示例。

## 8. 最小实验与评估

| 组别 | 输入 | 目的 | 实施顺序 |
|---|---|---|---|
| A | 问题 + 原图 | 直接 VLM 基线 | 第一批 |
| B | 问题 + EvidenceCard | 纯工具证据消融 | 第一批 |
| C | 问题 + 原图 + EvidenceCard | 联合输入主设置 | 第一批 |
| D | 问题 + 原图 + 同内容的扁平文本 | 控制事实内容，检查结构化组织的价值 | 第二批 |
| E | C + 相关辅助图 | 检查定位收益、遮挡与成本 | 后续 |
| F | 先问题+原图形成冻结观察，再联合输入 | 比较证据引导/冲突处置 | 后续 |

第一批目标是在同一冻结清单上运行三种模型 × A/B/C，共九种条件。三个条件已有 evaluator 路径：A 使用独立 image-only baseline，不经过路由、工具或 Claim verifier；B 使用 evidence-only 的受约束 VQA 路径；C 使用 image+evidence 的主路径。输出和指标按模式隔离，不能混池。Q4 调试稳定后，需显式开放 P9 VQA 执行并冻结 P9 合同，才能检验多工具证据。

消融必须控制模型版本、样本、问题、图像处理、解码、答案预算和评估规则。D 组尽量保留与 C 相同的事实、来源、单位和限制，避免同时改变内容与格式；研究来源或条件的效果时再单独消融。

分别报告：

- 原始模型答案与参考的匹配率；受核验回答与参考的匹配率；工具答案与参考的匹配率；最终系统正确回答数 / 全部请求数。
- 覆盖率=已回答数/全部请求数；条件准确率=正确回答数/已回答数；零回答时条件准确率记未定义。
- 冲突检出、复核率、拒答率、工具失败后的行为、引用有效率、数值/单位一致性。
- P9 的连续数值误差与拒答覆盖单独报告；流程通过不能代替医学准确性。
- 延迟、图像/文本 token 和模型调用数。

同一患者/图像可能对应多个问题，应按患者或至少图像聚类估计不确定性；当前 Q4 evaluator 对完整患者 ID 的输入提供等权患者均值与患者级 bootstrap 区间，ID 只留在 evaluator 内存中，不写入逐例结果。开发数据与冻结测试用途分开。参考标签/答案留在 evaluator，不能进入 EvidenceCard、Gate 或 consumer。训练重叠可以接受作流程开发，但必须披露，不宣称独立泛化；当前 400 张数据是开发流程集，不是独立 test。

### 8.1 证据干预压力测试

在独立标记的副本中替换 PA/AP、改错数值、交换左右、移除有效性条件、加入无关节点，测量错误证据是否带偏答案。干预不能覆盖原始图或真实工具结果。改动原始观察后的关系应按需要重算；“内部一致但错误”的预测与“结构/哈希损坏”的输入分别统计。

记录错误证据服从率、拒答/复核率，以及“无工具时正确、注入错误证据后答错”的比例。自然工具错误另做一层分析；合成干预不能代替真实错误病例。

## 10. 可以主张的研究方向

候选贡献是：基于 FunctionSpec 选取可追溯的相关证据子图，与原图联合输入，按证据类型执行冲突/适用条件检查，并用证据干预验证收益和失败边界。

“图像+问题+工具文本”已有先例；“最优”“新颖”“提高准确率”都需要对照与进一步相关工作核查。现阶段将其写为待验证假设。
